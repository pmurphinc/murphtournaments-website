Privacy Policy

Podcast Shorts Studio is a personal tool that runs on its operator's own computer and publishes short videos to that operator's own accounts. It has no users other than the person who installed it.

What this software is

Podcast Shorts Studio prepares short vertical videos from footage its operator already holds, and uploads them to social accounts that the same operator owns. It runs entirely on a personal computer. There is no hosted service, no shared server, and no account to sign up for.

Because it is installed and run by one person on their own machine, the only data it handles is that person's own. It does not collect information about anyone else.

What it stores, and where

Everything is stored on the computer it runs on. Nothing is stored anywhere else.

  • Video files the operator supplied, and the vertical versions made from them.
  • Transcripts produced locally by speech recognition, used for captions and titles.
  • Access tokens for the accounts the operator connected, encrypted on disk.
  • A record of what was published: titles, descriptions, timestamps, and the view and like counts the platforms report back.

What it sends, and to whom

It contacts only the services the operator connected it to, and only to do what they asked:

  • YouTube and Google — to upload a video to the operator's own channel, to read back how it performed, and to correct a title or description afterwards.
  • Instagram and Facebook (Meta) — to publish a Reel to the operator's own professional account and read its metrics.
  • TikTok — only if the operator connects it; otherwise the software prepares a file to upload by hand and contacts TikTok not at all.
  • Google Drive — only to read a folder the operator pointed it at.

No analytics service, advertising network, error-reporting service or third-party backend is used. There is nowhere for data to go that the operator did not choose.

Hosting a clip for Instagram

Instagram does not accept a file upload; it fetches the video from a web address. To publish there, the software uploads the clip to a storage bucket belonging to the operator, under a random unguessable name, and deletes it immediately afterwards — whether publishing succeeded or failed. For the seconds in between, that one file is readable by anyone holding the exact link. No other platform requires this and no other file is ever exposed.

Google user data

The software requests only the access it needs to do its job on the operator's own channel: permission to upload a video, to read the channel's own data back, and to edit or remove a video it published. Google offers nothing narrower for editing, so that permission also allows deletion; the software never deletes anything unless explicitly instructed to, and records it when it does.

Google data obtained this way is used only to publish and manage the operator's own videos. It is never sold, never shared with anyone, never used for advertising, and never used to train any model. Tokens are stored encrypted on the operator's computer and nowhere else.

Access can be withdrawn at any time by disconnecting the account inside the software, which revokes the grant and deletes the stored token, or from Google Account permissions.

Keeping and deleting data

Files and records stay on the operator's computer until the operator removes them. Deleting the application's data folder removes everything it holds. Videos already published to a platform live under that platform's own terms and must be removed there.

Children

This is a tool for publishing a person's own video work. It is not directed at children and collects nothing from them.

Changes

If what the software does with data changes, this page changes with it.
